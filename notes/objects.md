# Object system (enemies, shots, effects) - as ported in `port/mm4-core/src/objects.rs`

Conf: **C** = confirmed by frame-exact comparison with the real game (`mm4 --verify-obj`), **L** = read from code only.
Addresses are CPU addresses; "line" refers to `megaman4-disassembly/bank38_3F.asm`. Helper tools: `tools/asm.js <addr>` (compact listing),
`tools/ai_states.js <rom> <aiId>` (which routines/states an AI id reaches), `harness/dump_enemies.ps1`.

## Slots and arrays (C)
Slot 0 = Mega Man, 1-7 shots/effects (slots 1-4 never take damage, loop `$3A8097` starts hit checks at slot 5), 8-23 enemies and anything else.
Arrays are `$18` apart: `$0300` type/AI id, `$0318/$0330/$0348` X sub/px/page, `$0360/$0378/$0390` Y sub/px/screen, `$03A8/$03C0` X speed,
`$03D8/$03F0` Y speed (**positive = up**), `$0408` hitbox (bit 7 hurts Mega Man on contact, bit 6 can be hurt, bits 0-5 size index), `$0420` move flags
(1 right, 2 left, 4 down, 8 up), `$0438` placement-list index (`$FF` = none), `$0450` hit points, `$0468..$0510` 8 scratch bytes, `$0528` flags
(bit 7 = on screen this frame, bit 6 = flip, bit 4 = despawn when off screen, bit 3 = wider off-screen margin, bit 2 = invisible/no animation),
`$0540/$0558/$0570` animation frame / id / tick, `$0588|$05A0<<8` the **address of the routine that runs next frame** (AI is a chain of
states: each state stores the next state's address; the Rust port dispatches on that address), `$05B8` hit-flash/freeze timer (bit 7 = frozen).

## One game frame (C, `code_3EC6C7`)
1. player (bank `$3C`) 2. **AI loop** (bank `$3A`, `$8003`): for slots 1..23 with `$0300 != 0`: if `$05A0` < `$80` load the start address from `$8683/$8753 + type`; unless `$05B8` bit 7:
   switch bank `$A000` to `$85B3 + type`, `JMP ($0588)`. Slots >= 5 then get the shot-collision test (`$3FFA34`) and the contact test (`$3FF95D`, damage `$3A81CC`).
3. camera 4. **spawner** (bank `$38`) 5. fixed-bank updates 6. **draw pass** (`$3EDB3A`): despawn rules and animation tick per object (order alternates with `$95` parity; irrelevant for logic).
7. yield (`$3EC7C6`). The random task steps once per video frame *after* the logic.

## Spawner (C, `code_388000/388080`)
Two cursors `$9E` (first entry beyond the right edge) / `$9F` (first entry inside the window) walk the sorted placement list (`$B100..$B280` in the stage bank) when the camera moves;
direction `$2F` (set by the camera code: 1 right, 2 left, stays until the next scroll). New entry: no duplicate list index among slots 8-23, free slot = highest free index 8..23 (`$3FFB5C`),
"defeated" bit in `$0100+` blocks it. Initialisation: flags/type/hitbox/hp/anim/speed from the bank-`$38` tables (`$817F,$820F,$829F,$832F,$83BF,$844F`), facing Mega Man (`$3FF4DC`), Y speed -1.0, stale sub-pixel bytes are **not** cleared.

## Despawn / animation (C, `code_3EDB72-3EDD48`)
Objects with flag `$10` are removed when more than one page away horizontally (or `$30` px beyond the page edge when flag `$08`), or when the Y screen is below the screen;
exceptions: anim ids `$55,$71`, types `$26,$96,$99,$BB,$BC,$4D`. Removal (`$3EDC00`) clears `$05A0,$0300,$05B8,$0450` and sets `$0438=$FF`; position and speed bytes stay (stale data matters for the next object in that slot).
Animation: `anim.rs`; a frame whose sprite id is 0 ends the object (explosions); `$05B8` counts down and freezes the tick while bit 7 is set.

## The carry flag leaks (C)
Several AI routines use `ADC`/`SBC` without `CLC`/`SEC`. The AI loop's `CMP $F6` before each routine leaves `C = (bank >= previous bank)`; helpers leave their own carries
(`$3FF4DC` = obj >= player, `$3FF4F6` = old bit 2 of the direction, `$3FF6E6` = player >= obj, collision helpers = hit). The port keeps `World::carry` for this.
Random numbers: `$E4-$E7` 32-bit shift register (`$3EC4D9`), modified by AI (`$E4`, `$E5`) and **clobbered as scratch (`$E6/$E7`) by the shot-collision routine `$3FFA34`** whenever a live shot exists.

## Verification method (C)
`harness/gen_ptrace.js` with `OBJ=1 INVINCIBLE=1` logs player + all object slots at the end of every **logic** frame (breakpoint `$C7C6`), so lag frames do not matter.
`mm4 --verify-obj ptrace_x.txt` replays the objects with Mega Man's position from the trace and compares every byte of every live slot, the random state, cursors and `$95`.
The random task steps once per video frame; the number of steps between two rows is `Δ$92` (frame counter). When a logic frame is long (many objects) a video-frame boundary can fall *inside* it, so the AI saw the random state / `$92` of before the boundary: the verifier also tries "j steps before the frame, the rest after" and `$92 - 1`, and requires that one combination reproduces every byte of the row. (Found with item drops, which mix `$92`, `$95` and `$E5-$E7`.)
Runner: `harness/enemy_test.sh <rom> <frames> <seed..>` with ROM variants from `harness/make_enemy_rom.js <stage> <out> <types>` (`TELEPORT=page,x,y` to start elsewhere).

## Shots, damage, death, items (C, ported 2026-10-07)
- **Buster shot** = object type 2 (AI `$3A8825`), made by the player code (slots 1-3), 4.2 px/frame, no tile collision (it only despawns off screen or on an enemy). Deflected shots are type 3 (`$3A88C9`).
- **Shot vs enemy** (`$3A8097` for slots >= 5, `$3FFA34`): for the weapon's shot slots (3..1) alive with flag bit 7 and type != 3 against an enemy with flag bit 7 set and bit 2 clear: `$E6/$E7` (!) are overwritten with the shot's half height/width + the enemy's sizes (`$FACE/$FACF` by shot hitbox, `$FADC/$FB1C` by enemy hitbox), hit when |dx| < `$E7` and |dy| < `$E6`.
  Damage table = `$B700 + AI type` in the weapon's bank (`$20 | weapon`, buster = bank `$20`). Enemy hitbox bit 6 = vulnerable: vulnerable + damage -> `$3A82A4`; otherwise (armour or damage 0) the shot is deflected (`$3A8162`: becomes type 3, flies back/up).
  Damage: normal shot dies on hit; charged shots (anim `$20/$23`) deal 3x and survive if the enemy has more hp than that. `hp -= damage`, `$05B8 = 8` (flash). At 0 hp the enemy is despawned and replaced by type `$84E3+type` if non-zero, else becomes the explosion (type `$9D`, anim `$19`, sound `$27`).
- **Explosion `$9D`** (`$3BBB6C`): on animation frame 4 it rolls an item with `E7 = (E6 + E7 + 1 - $95 - ...) ...` mixing `$95`, `$E5` and the video-frame counter `$92`, `% 50` against thresholds `$BC8D = 14,10,8,3,2`: items anim `$1D` (small energy), `$1A` (big life 10 units), `$1B` (small life 2), `$1E` (1UP), `$1C` (big energy); no item if the roll is >= 14. The item stays in the same slot (still type `$9D`, state `$BBC3`: falls with probe `s0`, blinks when `s1 < $3C`, vanishes at 0).
- **Pickup** (`$3BBBDE`, also placed items `$C1` at `$3BBC4A`, which set the "defeated" bit `$0100 + idx/8` so they do not respawn): life refills 1 unit per 4 video frames (the game is frozen meanwhile; p95 advances one per unit), `$A1` lives (max 9), `$A2` E-tanks; weapon energy does nothing for the buster. Weapon-unlock items (anim >= `$51`) and boss-reward state (`$11`) are not ported.
- **Contact damage** (`$3A81B2` -> `$3A81CC`): enemy hitbox bit 7, player `$3C == 0`, `$30 < 6`, player anim != `$27`, `$3FF95D` overlap; damage `$3A8413 + type`. The player's reaction is applied **inside the AI loop** (so particles/sparks can still run in the same frame); the spark effect (type 1, anim `$12`, slot 5) appears at the **enemy**.
- **Death** (damage >= life): `$30 = 7`, `$B0 = 0`, player flag bit 2 (hidden: no animation tick), 16 particles (type `$2E`, AI `$3DA8C3`: 16-bit signed straight line, despawn when Y screen != 0; speeds from `$83D3/$83E3/$83F3/$8403`), `$0133 = 300`. The state handler does nothing; the main loop counts `$0133` down each frame and at 0 restarts the stage (`$3EC541`): objects 1..23 cleared (stale bytes kept), `$1F` = checkpoint index (page of `$C88B + 2*stage + n` passed), restart page/section from `$C8A7 + 4*cp + 8*stage`, spawner cursors `$9E = $9F = $B300[page]`, new life: teleport-in state `0A` at x `$80` of that page, sub-pixels and `$31` unchanged; lives `$A1 - 1`.

## Boss-room entry `$B8` and the stage-2 boss `$7E` (session 7; C = frame-exact against the real game, seed 681 3000 frames)
- **Boss-room object `$B8`** (AI `$35A7F9`, bank `$35`; placement type `79`, section 9 of stage 2). First state `$A7F9`: `code_3FFD9C` puts Mega Man into **player state 9** (`$30`; only from the ground, state 0; `$0146` = the slot) and the object falls in
  from the top of the room (gravity `$40`, no collision until Y >= `$80`, then the floor probe `$0A`; animation `$A8AC[stage]` = `$46` for stage 2). On landing: `$95 = 0`, `$BF = 0`, `$0132 = $8F` and state `$A84F`. There, on animation frame 5, every 8th `$95` it adds 1 to `$BF` (sound `$29`); when `$BF` = `$1C` the object **turns into the boss**:
  type `$A8BC[stage]` (`$7E`), animation `$A8C4` (`$29`), hitbox `$A8CC` (`$F6`), X speed `$A8E6:$A8DE` (`1.80`), hp `$1C`, Y speed -1.0, and Mega Man gets state 0 back. Total about 300 frames of frozen player.
- **Boss life meter**: the third HUD meter (x `$28`, attribute 2) is drawn when `$0132` bit 7 is set, with `$00B0 + ($0132 & $7F)` = `$BF` as the value (`$0132 = $8F` -> `$BF`). Ported in `Game::sprites`.
- **Player state 9** (`code_3C86AD`): vertical step with the floor probe, animation 1 if landed, facing right (`$31 = $0420 = 1`), buttons ignored. `Player::wait_step`.
- **`$EF`** (sprite priority line, parts lower than this are drawn behind the background) is *not* reset every frame: `code_3ECB59` zeroes it when a flag-`$10` section starts, the boss's first state sets `$B8`. Port: `World::ef_override` (None = stage table), cleared on restart.
- **Boss `$7E`** (bank `$38` `$A000`, file `port/mm4-core/src/objects/boss7e.rs`; states are named by their addresses): idle `$B04D` (timer `$0468`) -> `code_3FF71E`-style choice (`$B71E/$B724`: face Mega Man, row by distance `<$40/<$80/far`, column `(E7+E4+E5) & 7`, move = animation `$B28F[row*8+col]`:
  `$2F` jump at Mega Man (`$B104/$B137`, X speed = (dist+$20)/$37 per frame via the division `code_3FFC3A`, Y speed 6.9), `$2A` high leap (`$B146/$B16B`, lands, makes dust `$82`, sinks 1 px/frame to Y `$D0` (`$B1C8`), hides ~210 frames (`$B1F4`), re-emerges at Mega Man's X clamped to `$20..$E0` (`$B23C`)),
  `$30` walk and throw (`$B06E/$B087`: 42 frames, at animation frame 1 a `$7F` shot, 26 more frames, repeat; a wall ends it). Every move ends in `$B26D` (face Mega Man, idle 30 frames).
  Children: `$82` dust (`$B2E3`, sheds three `$CC` particles; `$CC` uses the static AI `$8823`), `$7F` shot (`$B2AF`, bursts into `$83` on a wall or a 1-in-4 roll every 20 frames; the `ADC` uses the AI loop's carry), `$83` burst (`$3A9F85`, makes nine `$80` puffs).
- `$B330`-`$B8xx` in the same bank are the **other stages' bosses** (`$A8BC` table: stage 0 `$8B`, 1 `$8D`, 2 `$7E`, 3 `$84`, ...), not more states of `$7E`; `$7E` dies into type `$77` (`$84E3` table), whose AI (`$35AFD4`) clears the other objects, closes the fight and starts Mega Man's victory state `$0B`.
- **Boss damage rules** (`code_3A82A4`, port `damage_enemy`): the shot always dies, but a boss (slot `$0146`, `$0132` bit 7) ignores hits while its flash timer `$05B8` is non-zero; a hit sets `$05B8` to `$30`, `$BF` = boss hp (the HUD meter), and the draw pass shows the stage's flash silhouette (sprite `$DD5E[stage]` = `$DF`) on frames where bit 1 of the timer is set instead of blinking.
- **Defeat** (`$77`, AI `$35AFD4`, port `boss_defeat`/`boss_b051`): kills slots 6-23 except itself, 16 `$2E` particles from slot 23's position (speed tables `$AF94/$AFA4/$AFB4/$AFC4`, highest free slots first), `$0132 = 0`, anim 0, then every frame `$B051`: waits until Mega Man's state < 3 and every other slot 5-23 is empty, then Mega Man gets state `$0B` and his shots are removed (verified).
- **Victory (session 8, all frame-exact)**: `$B051` hands Mega Man state `$0B` (`start_victory`: `$0148 = $FF`, `$0420` = 1 if X <= `$80` else 2). State `$0B` (`$3C87A7`, `Player::victory_step`): gravity, animation 7 in the air / 1 while `$0148` counts down / 4 walking (set only if it differs, no shooting offset), walks to X `$80` (blocked by a wall: vy 5.0), then jumps with vy 8.0. While falling at X `$80`, Y > `$6C` the game **overwrites Y with `$6C`** and only restores it when slots 8-23 are all empty (otherwise Y stays `$6C`); then anim 4 -> state 8. `$B093` (object side, `boss_b093`): when Mega Man is falling at X `$80`, Y `$6C` the `$77` object makes four `$2A` sparkles (offset tables `$B188`/`$B213`, mirrored for `$0468 >= 2`, AI `$B0F4`, `sparkle_b0f4`) and removes itself. The main loop (`code_3EC7DD`) counts `$0133` down in states 7 **and 8**; at 0 it runs the stage-end code `JSR $8003` (weapon get / stage select, not ported) and restarts the stage like after a death but without losing a life. The harness trace after that point is not comparable (the harness re-enters the stage through the menus); the verifier reports `stage clear` when the port's countdown ends on the same row.

## Session 11 (stage 5): new engine rules, all Mesen-verified
- **Life-item refill runs inside the AI loop** (`code_3BBC11`): for each unit `INC $B0,x`, `JSR $3FFCE3` = one full draw pass (`$3EDB3A`: despawns objects that left the screen, `$95`, sprites) + wait 1 frame, `LDX #3 / JSR $3FFF15` = 3 more frames. During these draw passes `$6B` (the unit counter) is non-zero, and `code_3EDC67` then **skips the animation tick** (`LDA $6B / BNE`). So objects keep their animation tick, shots that left the screen despawn *before* the later slots' shot tests, and the random task steps 4 times per unit between two objects' AI. The port: `World::life_refill` (called right after the AI of the slot that created `Pickup::Life`), `loop_steps`, `life_add`.
- The weapon/shot-collision test (`$8097`) runs for slot X after the AI returns even when the AI removed the object (stale flags/hitbox are used); it is skipped only if a routine leaves X different (not the case for the pickups).
- **Solid objects** (`code_3FF7D8` vertical, `code_3FF843` horizontal, called from the player's move routines only, slot X = 0): scan slots 23..1 for `$0300 != 0`, `$0390 == 0` (screen row 0), `$0528` bit 2 clear, bit 1 set (bit 0 only for vertical = one-way platform that only counts while he falls and never from below). `$10` = |dx| from `$3FF89A` (**its Z flag is only "page difference is even"**), `$11` = |dy|, `$12` = half height (`$F9B4`, minus 2 while sliding, minus 4 more when he is below the object centre). Horizontal hit: `dy < height` and `width >= dx`, depth `width - dx` (max 8); vertical hit: `dx < width` and `height >= dy`, depth `height - dy` (max 8). After a push the move routine compares old and new position to decide which tile probe runs (right move: `old > new` -> left-side probe else right-side probe; left move: `old >= new` -> left probe else right probe; falling: `old > new` -> head probe else the normal ground probe, then **vy = -2.0**; rising: `old < new` -> feet probe else head probe, then vy = -1.0). Objects never collide with solid objects (the `CPX #0` guards).
- **Stage 5 enemies**: `$73` ($AFB7: waits 60 frames, then every 21 frames creates a `$74` piece at Y `$E8` that rises (dir 8, flag bit 1 = solid) to `ypx + $B13C[k]` and stays `$B144[k]` frames, `k` = 0..3; the one with anim `$A8` becomes the `$A9` burst (hitbox `$14`), which holds on frame 12 for 600 frames, plays `$AA` and drops four falling pieces (dir 4, delays `$3D,$29,$15,$01`)). `$B4` ($B622: when Mega Man is within 32 px and `$013C|$013D == 0` it creates a `$B2` projectile every 120 frames: rises 42..64 frames, then falls with a 11-frame left/right swing, `$B6E1`). `$48` ($A3FD: walks 64 frames or to a wall, turn animation `$77` -> `$76`; shielded: hitbox bit 6 is set every frame and only cleared when a shot hits from the side it faces).
- In vertical sections Mega Man's X page is the screen number; the camera page equals it. Harness teleports must use x = 128 there (camera low byte 0).
- **Sway** (stage 5 section 3, page 12; AI `$5E` `$3DAEA3/$AEB7`): first state sets `$1C = $18`, `$1B = $80` (a request for the NMI's column renderer, `code_3FE35C`: each video frame it clears bit 7, draws four columns and adds 4 to `$1B`; when `$1B` is `$40` at the start of an NMI it sets it to 0). The object follows Mega Man's X, and when `$1B == 0` it sets `$F0 = 4`, `$F1 = $C0`, speed 0.5 px, direction up, `$013F = 4`, counter `$80`; afterwards it moves, flips direction (`dir ^= $0C`, `$013F ^= $0C`) every 128 frames and publishes `$FA` = its Y (vertical scroll), `$FD` = 2 if Y != 0, `$013E` = -(Y + $10) (0 when Y = 0). **While `$F0 == 4` all tile probes lower the entity's Y by `$013E`** (`code_3ED552` for vertical probes: unconditional unless `$013F` bit 2 is set or the page is `$0C`, then only above Y `$B5`, `$B7` while sliding; `code_3ED566` for horizontal probes: only above that limit; the limit uses the *player's* state `$30` also for objects). The subtraction is 8-bit: a head probe above the top then looks up rows `$F0-$FF` (carry replaces the `$F0` limit for negative probe offsets). The crush check (`code_3A805A`) is skipped below that limit. `$F0` is never cleared when the object despawns (the shift stays for pages 13+, Mesen-verified only for page 12).
- **Item carrier `$42/$43`** (`$3BA2B9`): drops to the floor (`$F0F8` id `$0E`, wall turn id `$22`), when Mega Man is within 32 px plays anim `$59`; on its frame 4 it drops a `$44` item (anim `$A3B5 + (E5 + E7) & 15`, or `$A3C5` for `$43`; `$E7` is overwritten by that sum; the item inherits the placement index so picking it up marks the carrier's placement as taken), on frame 7 it hovers 80 frames and flies up (`$6D`, `yv += $40` per frame) until it leaves the screen. The item `$44` ($A3D5): falls (id `$0E`), wall id `$18`, then runs the `$BC4A` pickup AI.
- **Video-frame boundaries inside the AI loop** exist: a logic frame can be interrupted by the NMI between the AI of one object and its shot test (seed 1051), which changes what the object's AI sees (`$1B`) and the final `$E6/$E7`. The verifier's `pos` search models it.
