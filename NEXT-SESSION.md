## Pitfalls (still valid)
- `MM4_SECT2B` must be the hex `$2B` of the recording's section; stage 14 hurt recordings need the pod bits poked (`102=FF,103=FF`, see `rec_s14_b.sh`).
- A verifier mismatch of rng right after a long scene change can mean more skipped NMIs than tried; extra full frames inside one logic frame must call `draw_phase` + `rng_step` + `loop_steps += 1`.
- The recorder's `BOSSHP` hook runs after every video frame; interrupted recordings leave truncated trace lines (re-record them).
- `sh` reads a running script incrementally: do not edit a script while a batch uses it (copy it first).
- Chain scripts: the console frame numbers are what `chain_X.txt` contains; the Rust flow starts 6 frames after power-on (`--lag 6`); forced events (`--clear-at`, `--gameover-at`, `--aa`) have to be given in the flow's own frame count (console frame - 6). A forced stage clear skips that frame's logic (the real hijack does too); a forced game over (state 7 poked) shows no dying sprite.
- Quirks of the real code that were *reproduced on purpose*: weapon 6/11 take the highest free shot slot while the buster takes the lowest; the Flash Stopper's timer only counts while the weapon routine runs; the pause menu would loop forever on an empty column (the port stops after 64 steps); the console shows Mega Man's sprites one frame late while he teleports in and his idle blink one frame late; the stage logic reads buttons one frame late.
